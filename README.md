# Лабораторна робота: Error-handling bottlenecks

## Реалізовані принципи:
- Ідемпотентність: повторні POST з тим самим `Idempotency-Key` повертають той самий результат.
- Кожна відповідь містить заголовок `X-Request-Id`; у тілі помилки він дублюється.
- При перевищенні ліміту повертається `429` з `Retry-After`; клієнт чекає і повторює.
- Клієнт застосовує таймаут (`AbortController`) і обмежену кількість ретраїв із експоненційним backoff та джитером.
- На фронті реалізований degraded mode (банер/стейт після N поспіль 500ів, тимчасово дизейблені кнопки).
- `GET /health` повертає `{"status": "ok"}`.
